# 영상 다듬기 2 — 박진감 V1.11.0 검증 기록

설계 스펙(`docs/superpowers/specs/2026-11-03-video-pace-design.md`) §9(검증)에 따른 기록 문서입니다. 영상 길이를 거리로 정하는 것, 거리 기준 빠르기와 볼거리 강약, 더 높고 천천히 도는 카메라, 초당 30장, 음악 박 읽기와 장면 맞추기, 앱에 든 기본 곡 세 곡(햇살 페달·바람길·언덕 너머)과 옵션 창의 길이 문구(최대 30초/1분/2분)를 다룹니다. DB는 바꾸지 않았습니다(9판 그대로).

> **경고**: `connectedDebugAndroidTest`는 끝나면 앱을 지워 그 휴대폰의 기록이 사라집니다.
> connected 테스트는 S22 `R5CT43TFS9A`에서만, S25 `R3CY903ZYQV`에는 아무것도 하지 않습니다(설치는 사용자가 요청할 때 DB·DataStore 백업과 표 개수 비교 뒤에).

### 만든 영상·이미지 삭제 (Galaxy S22 Ultra, 2026-11-04)

- `ui.video.TripMediaRowTest` 6개, `video.MediaStoreWriterTest` 4개 통과
- 앱이 만든 영상·이미지: 창 바깥 누르기, 아래로 밀기, [아니오]는 칸과 파일이 그대로. [예]는 칸과 파일이 함께 사라짐
- 앱을 지웠다 다시 설치한 파일(`owner_package_name` 없음), 사진 권한 허용: 이미지 칸이 보이고 [예] 뒤 Android 확인 창이 뜸. [거부]는 그대로, [허용]은 칸과 파일이 함께 사라짐
- 같은 조건의 영상과, 사진 권한이 없을 때의 이미지: 앱이 파일을 볼 수 없어 화면을 여는 때 칸이 빠지고 파일은 갤러리에 남음(이전부터의 동작). 이런 파일은 갤러리 앱에서 지움

### release 빌드

- `:app:assembleRelease`의 `resources.txt`에 `raw:music_*` 세 곡이 "reachable from keep xml file"로 남고, `aapt2 dump resources`에 `raw/music_*` 세 이름이 있음(`res/raw/keep.xml`, `BuiltInMusicResourcesTest`)
- 휴대폰에서 release로 기본 곡 영상 만들기는 확인하지 못함: release 빌드가 시작하자마자 멈춤(`IllegalAccessError`, R8). V1.10.0 release도 똑같이 멈춰 이번 변경과 무관한 이전부터의 문제로, 따로 고침

### S25 설치와 점검 기록 (2026-11-04)

- 설치: main `20686ee`의 debug(`1.11.0-dev`, 11100). 설치 전 DB·DataStore 백업, 기록 중 아님 확인
- 데이터: 점검 뒤 14개 표 가운데 `trip_media`는 시험 영상 4행이 늘었고(옛 4행 그대로) `segment_extras`는 사진 찾기 칸(`photosScannedAt`, `photoScanDone`)만 바뀜. 나머지 12개 표는 내용까지 같음
- 시험 영상(사용자가 지울지 결정): `Movies/bikeRecoder/`의 `bikeRecoder_20261103_2015.mp4`, `_2015_2.mp4`, `_2015_3.mp4`, `bikeRecoder_20261025_2047_3.mp4`. 옵션의 마지막 값은 햇살 페달, 사진 넣기 켬
- 발견: 영상의 거리 숫자가 끝 카드보다 큼(걷기 1.40 km와 1.34 km, 라이딩 1.62 km와 1.58 km). 숫자는 경로 길이(`Hud`의 `route.at`), 카드는 저장된 합계를 씀. V1.10.0부터 같은 계산이라 이번 변경 때문은 아니며, 따로 고칠 작업으로 남김

### S25 삭제 점검 기록 (2026-11-04)

- 설치: main `2581632`의 debug(`1.11.0-dev`). 설치 전 DB·DataStore 백업, 기록 중 아님 확인. 갤러리의 기존 영상 9개는 모두 앱 소유(`owner_package_name`)
- 11월 3일 아침 걷기에 시험용 영상과 이미지를 만들어 확인: 창 바깥 누르기, 아래로 밀기, [아니오]는 칸과 파일이 그대로이고, 짧게 누르면 전처럼 열림. [예]는 Android 확인 창 없이 칸과 파일을 함께 지움
- 영상을 지우면 요약 카드의 ▶와 공유 창의 영상도 사라짐
- 데이터: 시험 파일은 모두 지워 `Movies/bikeRecoder`, `Pictures/bikeRecoder`의 파일 이름과 크기가 점검 전과 같음. 14개 표 가운데 `segment_extras`의 사진 찾기 칸만 바뀌었고 나머지 13개 표는 내용까지 같음

## 판정

- PC 테스트와 기기 테스트가 통과하고 S22 비교 영상이 V1.10.0보다 나으며 점검표 7개 항목이 모두 합격이면 `CHANGELOG.md`의 V1.11.0을 확정하고(「미출시」 표기 제거) 태그를 붙입니다.
- 불합격 항목은 원인 수정과 회귀 테스트 추가 뒤 그 항목만 다시 확인하고, 여기에 재검증 결과를 덧붙입니다.
- S25는 사용자가 요청할 때 DB 백업과 기록 개수 비교 뒤에 설치합니다.
