## 0. 목적과 범위

사용자는 2019년부터 Relive로 자전거 기록을 남겼다(38회, 684 km). 이 기록을 이 앱으로 옮겨, [요약] 피드와 [통계](목표·연속 주간·기간 통계·누적 지도·개인 기록)에 이 앱에서 기록한 주행과 똑같이 잡히게 하고, 영상·요약 이미지 만들기와 공유하기도 하려 한다.

Relive는 활동마다 GPX를 내려받게 해 준다(relive.cc 설정 → 내 데이터 → Download GPX). 한꺼번에 받는 기능은 확인되지 않았고, 받은 파일의 확장자가 `.bin`·`.gps`일 수 있다. Strava의 전체 내보내기는 ZIP 하나이고 `activities/` 안에 `.gpx`, `.gpx.gz`, `.fit.gz`가 있다.

V1.6.0이 하는 일:
- 설정 탭과 파일 앱(공유·열기)에서 GPX·ZIP을 받아(§1.1)
- 찾은 주행을 확인 목록으로 보여 주고(§1.2)
- 고른 것을 앱의 기록 엔진으로 다시 계산해 여행으로 저장하고(§2)
- 가져온 기록을 표시하고 한 번에 지울 수 있게 한다(§4)

하지 않는 일:
- FIT 형식(Strava `.fit.gz` 등). 목록에 "GPX 파일이 아닙니다"로 나온다.
- 여러 파일을 여러 날 여행 하나로 합치기. 파일 하나가 여행 하나다.
- GPX 안의 심박·케이던스 확장 값 읽기. 심박은 기존 뒷정리(Health Connect)만 쓴다.
- 가져온 주행의 수정(자르기, 합치기). 지우기는 여행 하나씩(기존 기능) 또는 [모두 지우기].
- 서버·계정 연동(Relive·Strava 로그인으로 받아 오기).

## 1. 입구와 화면

### 1.1 시작하는 곳

- **설정 탭:** 새 묶음 "기록 가져오기"를 "공유" 묶음 아래, "앱 정보" 위에 둔다.
  - 줄 "지난 기록 가져오기 (GPX)", 설명 "Relive·Strava 등에서 받은 GPX·ZIP 파일". 누르면 시스템 파일 고르기 창(`OpenMultipleDocuments`, 형식 `*/*`)이 열린다. 여러 개를 고를 수 있고 GPX와 ZIP을 섞어도 된다.
  - 가져온 기록이 있으면 줄 "가져온 기록 N개"와 [모두 지우기](§4.3)를 더한다.
  - 가져오는 중이면 "지난 기록 가져오기" 줄 설명이 "가져오는 중 12/35"가 되고, 누르면 진행 화면(§1.3)으로 간다.
- **파일 앱:** 내 파일·다운로드에서 파일을 고른 뒤 '공유 → bikeRecoder'(`ACTION_SEND`, `ACTION_SEND_MULTIPLE`) 또는 '다른 앱으로 열기 → bikeRecoder'(`ACTION_VIEW`). 받는 형식은 `application/gpx+xml`, `application/xml`, `text/xml`, `application/zip`, `application/x-zip-compressed`, `application/gzip`, `application/octet-stream`이다(파일 앱이 `.gpx`를 이렇게 알려 준다).
  - 들어오면 확인 목록(§1.2)을 연다. 처음 안내(온보딩) 중이면 안내가 끝난 뒤 연다.
  - 가져오는 중에 또 들어오면 "가져오기가 끝난 뒤 다시 보내 주세요"를 띄우고 무시한다.

### 1.2 확인 목록 ("기록 가져오기" 화면)

- 맨 위 제목 "기록 가져오기", 뒤로 가기.
- 읽는 동안: "파일을 읽는 중… 12/38"과 진행 표시. 이때 뒤로 가면 읽기를 멈추고 화면을 닫는다.
- 다 읽으면:
  - 머리 줄 "찾은 주행 38개 · 새로 35개", 그 아래 작은 글씨 "파일 38개에서".
  - [전체 선택] 체크(고를 수 있는 줄 전부를 켜고 끔).
  - 줄은 시작 시각이 최근인 것부터. 읽을 수 없는 줄은 맨 아래에 모은다.
  - 한 줄: 체크 상자, 작은 경로 그림(44dp, 기존 경로 그림 재사용), 첫 줄 "2023년 5월 14일 (일) 오전 9:12", 둘째 줄 "32.1 km · 1시간 45분".
- 줄의 상태(§3.2의 판단):
  | 상태 | 체크 | 둘째 줄 |
  |---|---|---|
  | 새 주행 | 켜짐, 고를 수 있음 | "32.1 km · 1시간 45분" |
  | 자전거가 아님 | 꺼짐, 고를 수 있음 | "달리기 · 6.2 km — 자전거가 아님" |
  | 이미 있는 주행과 겹침 | 꺼짐, 흐림, 고를 수 없음 | "이미 있는 주행과 겹칩니다" |
  | 목록에 같은 주행 | 꺼짐, 흐림, 고를 수 없음 | "목록에 같은 주행이 있습니다" |
  | 읽을 수 없음 | 꺼짐, 흐림, 고를 수 없음 | 이유(오류 색, §5) — 첫 줄은 파일 이름 |
- 맨 아래 단추 "N개 가져오기"(N = 체크한 줄 수). 0개면 흐림. 찾은 주행이 하나도 없으면 목록 대신 "가져올 주행을 찾지 못했습니다"와 [다른 파일 고르기].
- 화면 회전에도 목록과 체크가 남는다(화면 ViewModel이 들고 있다).

### 1.3 가져오는 중과 결과

- [N개 가져오기]를 누르면 같은 화면이 진행 상태로 바뀐다: "가져오는 중 12/35", 진행 표시, [멈추기].
- 화면을 떠나도 계속한다(§3.3). 다시 들어오면(설정 줄) 진행 상태를 보여 준다.
- 끝나면: "35개를 가져왔습니다" 그리고 건너뛴 것이 있으면 " · 건너뜀 3개"(가져오는 사이 겹치게 된 것, 저장 실패). 단추 [요약 보기](요약 탭으로)와 [닫기].
- [멈추기]를 누르면 저장 중인 주행까지만 저장하고 "12개를 가져왔습니다 · 멈춤"을 보인다.

## 2. 저장과 계산

### 2.1 주행 하나 = 여행 하나 + 구간 하나

- 여행: `SINGLE_DAY`, `COMPLETED`, 경로 성향은 설정의 기본값. `createdAt` = 첫 점의 시간, `lastActiveAt` = `completedAt` = 마지막 점의 시간. 경유지(stop)는 없다.
- 구간: 그 여행에 하나. `startedAt` = 첫 점의 시간, `endedAt` = 마지막 점의 시간, `localDate` = 시작 시각의 Asia/Seoul 날짜.
- 점과 합계는 §2.2의 다시 계산 결과다.
- 여행·구간·점·가져옴 기록(§4.1)을 한 트랜잭션으로 저장한다. 중간에 실패하거나 앱이 꺼져도 반쪽 주행이 남지 않는다.

### 2.2 다시 계산 (방법 A)

- GPX 점(`trkpt`)을 시간 순서대로 정렬해(같은 시간은 처음 것만) 새 `RecordingSession(startMillis = 첫 점 시간, autoPause = true)`에 넣는다. 각 점은 `onFix(fix, nowMillis = fix.timeMillis)`이고 마지막에 `stop(마지막 점 시간)`.
  - 자동 일시정지는 사용자 설정과 상관없이 늘 켠다(신호등·휴식이 이동 시간에서 빠지게).
  - 기압은 없다. 고도는 GPX `<ele>`(GPS 고도)만 쓴다.
  - 점의 정확도는 5 m, 속도·방향은 비운다(지금 `GpxParser`와 같다).
- 저장하는 점: 엔진이 기록 중 상태에서 채택한 점(`RecordingUpdate.point`)만.
- 합계: `stop` 뒤의 `stats`를 `SegmentTotals`로 바꾼 것(거리, 이동 시간, 경과 시간, 최고 속도, 상승·하강, 최저·최고 고도).
- 같은 점들을 실시간 기록으로 넣었을 때와 결과가 같아야 한다(§7.1).
- 여러 `trk`·`trkseg`가 있어도 점을 모두 모아 하나의 주행으로 계산한다. 끊긴 동안은 자동 일시정지로 이동 시간에서 빠진다.

### 2.3 가져온 다음 (기존 기능 그대로)

- 지역 이름·자동 제목: 요약 피드가 기존처럼 찾는다(예: "아침 라이딩 · 서울 강서구").
- 뒷정리(`PostProcessor`): 가져오기가 끝나면 `request()`를 한 번 부른다. 사진 찾기(그 시간대 갤러리 사진), 심박 읽기(Health Connect가 주는 범위만 — 오래된 기록은 대개 "없음"), 누적 지도용 단순화 경로.
- 통계·요약·이번 주 띠·연속 주간·개인 기록·🏆은 저장된 구간에서 계산되므로 바로 반영된다.
- 영상·요약 이미지 만들기와 공유하기: 완료 여행이므로 그대로 된다.

## 3. 파일 읽기와 판단

### 3.1 파일 종류 판단 (내용으로)

- 앞 몇 바이트를 본다.
  - `PK\x03\x04`: ZIP. 안의 항목을 하나씩 같은 방법으로 판단한다(폴더는 건너뜀). ZIP 안의 ZIP은 읽지 않고 그 항목을 "GPX 파일이 아닙니다"로 둔다.
  - `\x1f\x8b`: gzip. 풀어서 다시 판단한다(한 번만).
  - 그 밖: 앞 4 KB(BOM과 공백 건너뜀)에 `<gpx`가 있으면 GPX. 없으면 "GPX 파일이 아닙니다".
- 목록 줄의 "파일 이름"은 고른 파일의 표시 이름, ZIP 안이면 "묶음.zip / activities/123.gpx".
- 제한:
  - 파일·항목 하나(풀었을 때) 50 MB. 넘으면 "너무 큰 파일입니다".
  - ZIP 하나의 항목 2,000개. 넘는 항목은 읽지 않고, 목록 맨 위에 "묶음.zip: 항목이 너무 많아 처음 2,000개만 읽었습니다".
  - 한 번에 찾는 주행 500개. 넘으면 나머지는 읽지 않고 "주행이 너무 많아 처음 500개만 보여 줍니다".
- XML 외부 참조(DOCTYPE, XXE)는 막는다(지금 `GpxParser`의 설정과 같다).

### 3.2 주행 판단

- **시간:** GPX 시간(ISO-8601, 보통 UTC)을 epoch 밀리초로. 시간이 없거나 읽을 수 없는 점은 버린다. 버린 점이 전체 점의 절반을 넘으면 "시간이 없는 기록입니다".
- **좌표:** lat −90~90, lon −180~180 밖이거나 숫자가 아니면 그 점을 버린다.
- **너무 짧음:** 엔진이 채택한 점이 2개 미만이거나 거리가 10 m 미만이면 "너무 짧은 기록입니다"(요약·공유의 10 m 기준과 같다).
- **자전거인지:** 첫 `trk`의 `<type>` 글자(대소문자 무시, 앞뒤 공백 제거).
  - 없거나 비었으면 자전거로 본다(Relive 파일에 없을 수 있다).
  - 자전거: `cycling`, `biking`, `bike`, `ride`, `road_biking`, `mountain_biking`, `virtualride`, `ebikeride`, `gravel_cycling`, `1`(Strava 숫자) 등 — `bik`·`cycl`·`ride`를 포함하면 자전거.
  - 그 밖(`running`, `walking`, `hiking`, `swimming`, `9` 등)은 자전거가 아님. 목록 둘째 줄의 활동 이름은 `running`→달리기, `walking`→걷기, `hiking`→등산, 그 밖→"다른 활동".
- **이미 있는 주행과 겹침:** 이 주행의 [시작, 끝] 구간이 앱에 있는 어느 구간(기록 중인 구간 포함 — 끝을 "지금"으로 본다)의 [startedAt, endedAt]과 겹치면 겹침. 끝과 시작이 딱 맞닿는 것(한쪽 끝 = 다른 쪽 시작)은 겹침이 아니다.
- **목록에 같은 주행:** 고른 파일끼리 시간이 겹치면, 파일을 고른 순서(ZIP 안은 항목 순서)로 먼저 나온 것만 새 주행이고 나머지는 "목록에 같은 주행이 있습니다".

### 3.3 확인 목록은 요약만, 저장할 때 다시 읽기

- 읽는 단계는 모든 주행을 §2.2대로 계산하지만 화면에 쓸 요약(시작·끝 시각, 거리, 이동 시간, 활동, 상태, 작은 경로 그림용 단순화 점)만 남긴다.
- [가져오기] 때 고른 주행의 파일(또는 ZIP 항목)을 다시 읽어 계산·저장한다. 파일이 그사이 사라졌거나 내용이 바뀌어(시작·끝 시각이 다름) 읽을 수 없으면 그 주행만 건너뜀으로 센다.
- 파일 접근 권한: 고르기 창·공유로 받은 URI는 그 화면이 살아 있는 동안 읽을 수 있다. 진행은 앱 전체 작업(§3.4)이 하므로, 가져오기를 시작할 때 각 URI에 `takePersistableUriPermission`을 시도하고(되는 것만) 끝나면 놓는다. 권한이 없어 다시 읽지 못한 주행은 건너뜀으로 센다.

### 3.4 가져오기 작업

- 앱 전체에서 하나만 있는 작업(영상 만들기 작업처럼 `AppContainer`에 있는 단일 객체, 앱 범위 코루틴). 상태: 쉼 / 읽는 중(i/n) / 가져오는 중(i/n) / 끝(가져옴, 건너뜀, 멈춤 여부).
- 주행마다: 다시 읽기 → 다시 계산 → 저장 직전에 겹침 재확인(§3.2) → 한 트랜잭션 저장. 한 주행의 실패(읽기·계산·저장)는 로그만 남기고 건너뜀으로 센 뒤 계속한다.
- [멈추기]: 지금 주행의 저장이 끝난 뒤 멈춘다.
- 다 끝나면(멈춤 포함, 하나라도 저장했으면) 뒷정리 `request()`.
- 영상 만들기·기록 중에도 할 수 있다. 앱 프로세스가 죽으면 거기서 멈춘다(저장된 주행은 남는다). 다시 시작하지는 않는다.

## 4. 가져온 기록 표시와 지우기

### 4.1 DB 8판

- 새 표 `trip_import`:
  - `tripId` INTEGER PRIMARY KEY, `trip(id)` 외래 키 `ON DELETE CASCADE`
  - `fileName` TEXT NOT NULL (목록 줄의 파일 이름, 200자까지)
  - `importedAt` INTEGER NOT NULL (epoch ms)
- 7→8은 자동 이전(AutoMigration). 기존 표·행은 그대로. 스키마 `8.json`을 내보낸다.

### 4.2 표시

- 요약 카드 날짜 줄 끝에 " · 가져옴": "2023년 5월 14일 (일) 오전 9:12 · 가져옴".
- 여행 기록 화면 제목 아래에 "Relive_0514.gpx에서 가져옴"(작은 글씨, `fileName`).
- 그 밖(통계, 영상, 공유 글)은 구분하지 않는다.

### 4.3 [모두 지우기]

- 설정 "가져온 기록 N개"의 [모두 지우기] → 확인 창 "가져온 기록 N개를 지울까요? 이 휴대폰에서 기록한 주행은 남습니다." [지우기] [취소].
- 지우는 것: `trip_import`에 있는 여행 전부를 기존 여행 지우기와 같은 방법으로(구간, 점, 사진 연결, 심박, 단순화 경로, 이름표, 만든 영상·이미지 기록). 갤러리의 영상·이미지 파일은 남는다(기존 규칙).
- 가져오는 중에는 [모두 지우기]가 흐리다.
- 끝나면 "가져온 기록을 지웠습니다".
- 여행을 하나씩 지우는 기존 기능도 그대로 되고, 그러면 `trip_import` 행도 함께 지워진다(CASCADE).

## 6. 구조 (모듈과 책임)

- **core (JVM, 시험 쉬움):**
  - GPX 읽기: 지금 `GpxParser`를 넓혀 점(시간 없는 점 처리, 좌표 검사), 첫 `trk`의 `type`과 `name`을 돌려준다. 기존 시험·재생용 호출은 그대로 동작해야 한다.
  - 파일 종류 판단(§3.1, 바이트 배열·스트림 기준)과 ZIP·gzip 풀기(크기·개수 제한).
  - 다시 계산(§2.2): 점 목록 → 채택 점 + `SegmentTotals`.
  - 판단(§3.2): 활동 종류, 겹침(이미 있는 구간 목록과 고른 것끼리), 너무 짧음.
- **app:**
  - `trip_import` 엔티티·DAO·저장소, DB 8판, 한 트랜잭션 저장과 [모두 지우기].
  - 가져오기 작업(§3.4): URI 읽기(ContentResolver), 상태 StateFlow, 뒷정리 요청.
  - 화면: 설정 묶음, "기록 가져오기" 화면과 ViewModel, 카드·여행 화면 표시.
  - 매니페스트: `MainActivity`의 `ACTION_SEND`·`ACTION_SEND_MULTIPLE`·`ACTION_VIEW` 인텐트 필터(§1.1 형식), 들어온 URI를 `LaunchRequest`로 넘겨 화면을 연다.

## 7. 검증

### 7.1 PC 시험 (JUnit)

- GPX 읽기: Relive식(type 없음), Strava식(`cycling`, 숫자 `1`), 여러 `trk`·`trkseg`, 시간이 일부/절반 넘게 없음, 고도 없음, 다른 이름공간·접두어, XXE(DOCTYPE) 거부, GPX가 아닌 XML·HTML, 좌표 범위 밖.
- 종류 판단: `.bin` 이름의 GPX, gzip GPX, ZIP 안의 GPX·gz·폴더·ZIP, 50 MB 넘는 항목, 2,000개 넘는 ZIP, BOM.
- 다시 계산: 같은 점을 `RecordingSession`에 실시간처럼 넣었을 때와 거리·이동 시간·상승이 같다. 5분 쉰 주행의 이동 시간에서 쉰 시간이 빠진다. 점 순서가 섞인 파일도 같은 결과.
- 판단: 활동 문자열 표, 겹침(앞·뒤·안·밖·딱 맞닿음·기록 중 구간), 목록끼리 겹침의 순서, 너무 짧음(9 m / 10 m).
- 가져오기 작업(가짜 저장소·가짜 읽기): 고른 것만 저장, 저장 직전 겹침 재확인, 다시 읽기 실패 건너뜀, [멈추기], 한 주행 실패 뒤 계속, 상태 흐름, 끝난 뒤 뒷정리 1회, 하나도 저장 안 했으면 뒷정리 없음.
- 확인 목록 ViewModel: 체크 규칙, 전체 선택, 정렬(최근 순, 읽을 수 없음은 아래), N 계산, 제한 문구.
