# 자전거 내비게이션 설계 (하위 프로젝트 4 — 최우선 구현)

- 작성일: 2026-10-05
- 대상 버전: V1.0.0
- 상태: 사용자 검토 대기

## 0. 전체 프로젝트 맥락

bikeRecoder는 자전거 주행을 기록하고, 자전거도로 우선 내비게이션을 제공하며, 주행 경로를 사진·MP4 영상으로 만드는 개인용 안드로이드 앱이다. 서버는 없으며 모든 처리는 기기 안에서 한다.

전체 기능은 4개의 하위 프로젝트로 나누어 아래 순서로 각각 스펙 → 계획 → 구현 → 검증을 거친다.

| 순서 | 하위 프로젝트 | 버전 |
|---|---|---|
| 1 | **내비게이션** (이 문서) | V1.0.0 |
| 2 | 기록 코어 — GPS 기록, 실시간 지표, 자동/수동 일시정지, 음성 안내, 기록 목록/상세 | V1.1.0 |
| 3 | 여행과 후처리 — 여러 날 여행 묶기, 갤러리 사진 매칭, Health Connect 심박(Galaxy Watch7), 누적 경로 지도 | V1.2.0 |
| 4 | 영상과 이미지 생성 — 요약 이미지, Relive 스타일 3D 영상(속도 비례 재생, 사진 삽입), 기기 내 MediaCodec 인코딩 | V1.3.0 |

이후 단계에서 확정된 사항(참고용, 해당 단계 스펙에서 상세화):
- 사진은 휴대폰 기본 카메라 앱으로 찍고, 앱은 기록 시간대의 갤러리 사진을 촬영 시각·EXIF 위치로 경로에 매칭한다.
- 심박은 Health Connect에서 주행 후에 읽어온다(실시간 아님).
- 영상은 기록(여행)이 완료된 뒤에만 기기 안에서 생성한다.
- 기록 코어의 1km 음성 안내(평균 속도, 이동 거리, 이동 시간)와 내비게이션의 1km 안내는 한 문장으로 통합한다.

사용 기기: Samsung Galaxy S26 (Android 17), Galaxy Watch7.

## 1. 목표와 범위

### 1.1 목표
- 목적지까지 **자전거도로를 우선하는 경로**를 기기 안에서(오프라인) 계산하고 음성으로 안내한다.
- 여러 날에 걸친 여행에서도 "완료"를 누를 때까지 안내 상태를 유지한다.

### 1.2 포함
- 권한 온보딩, 경로 데이터(BRouter rd5) 다운로드
- 목적지 입력: 카카오 로컬 검색 + 지도 길게 누르기
- 경로 계획: 현재 위치 → 경유지(여러 개, 순서 변경) → 목적지, 경로 성향 3종
- 안내: 회전 음성 안내, 1km 정기 안내(이동 거리·남은 거리·도착 예정 시각), 경로 이탈 재탐색, 경유지/목적지 도착
- 여행(Trip) 최소 모델: 당일/여러 날 유형, 진행 중/완료 상태
- 경로 주변 지도 오프라인 다운로드와 자동 삭제
- 설정 화면

### 1.3 제외 (이후 단계)
- 주행 기록 저장, 사진, 심박, 영상 — 이후 하위 프로젝트
- GPX 코스 가져오기, 경로 이름 붙여 저장 — 현재 계획 없음
- 워치 앱, 실시간 심박 — 현재 계획 없음

## 2. 기술 선택

| 영역 | 선택 | 근거 |
|---|---|---|
| 언어/UI | Kotlin, Jetpack Compose | 표준 현대 안드로이드 스택 |
| 지도 | MapLibre Native Android `org.maplibre.gl:android-sdk` **13.6.1** (버전 고정), Compose `AndroidView`로 래핑 | 무료·오픈소스, 카메라 완전 제어(영상 단계 필요), 오프라인 지역 지원. 공식 Compose 래퍼(0.19)는 1.0 이전이라 사용하지 않음 |
| 지도 타일 | OpenFreeMap (`https://tiles.openfreemap.org/styles/liberty`) + 한국어 라벨 수정 스타일 | API 키·요청 제한 없음. 표기: "OpenFreeMap © OpenMapTiles Data from OpenStreetMap" |
| 타일 교체 대비 | `TileSource` 인터페이스 → `OpenFreeMapSource` / (대비책) `PmtilesSource` | OpenFreeMap 약관의 자동 수집 조항 해석이 불명확. 문제 시 PC에서 만든 한국 PMTiles 파일로 교체 |
| 경로 탐색 | BRouter **v1.7.10** 소스를 `third_party/brouter/`에 모듈로 포함 (MIT) | 자전거 전용, 오프라인, 프로필 커스터마이즈, 회전 정보(voicehints) 출력. JitPack 1.7.10 빌드 실패, GitHub Packages는 토큰 필요 |
| 경로 데이터 | `https://brouter.de/brouter/segments4/` 의 `E125_N35.rd5`(약 67MB), `E125_N30.rd5`(약 13MB). 선택: `E130_N35`(울릉·독도), `E120_N35`(서해 섬) | 한국 본토+제주 약 80MB |
| 장소 검색 | 카카오 로컬 REST API (`/v2/local/search/keyword.json`, `/v2/local/geo/coord2address.json`), 헤더 `Authorization: KakaoAK {키}` | 한국 장소 검색 품질 최고, 무료 하루 10만 건 |
| HTTP/JSON | OkHttp, kotlinx.serialization | |
| 저장 | Room(Trip, Waypoint, OfflineRegionRef), DataStore(설정) | |
| 위치 | Fused Location Provider, 위치 포그라운드 서비스 | |
| 음성 | Android TextToSpeech (Samsung TTS 우선, 한국어 미지원 시 Google TTS), `USAGE_ASSISTANCE_NAVIGATION_GUIDANCE` + `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK` | |
| 의존성 주입 | 수동 `AppContainer` | 규모 대비 단순, AGP 9 호환성 위험 회피 |

### 2.1 비밀 키 관리
- 프로젝트 루트 `secrets.json`: `{ "kakaoRestApiKey": "..." }`
- Gradle이 빌드 시 읽어 `BuildConfig.KAKAO_REST_API_KEY`로 주입한다. 파일이 없으면 빈 문자열로 빌드되며 검색 화면에서 키 미설정 안내를 표시한다.
- `secrets.json`은 `.gitignore` 등록, 견본 `secrets.example.json`은 커밋한다.
- 카카오 개발자 콘솔에서 **[제품 설정] > [카카오맵] 사용 설정 ON**이 필수다(2024-12-01부터).

### 2.2 Android 17 제약
- 백그라운드 오디오 제한: 보이는 액티비티에서 시작한 위치 포그라운드 서비스만 while-in-use 권한을 가지며 TTS가 동작한다. **안내 시작은 반드시 앱 화면에서** 한다.
- BOOT_COMPLETED 등 백그라운드에서 위치 포그라운드 서비스를 재시작할 수 없다. 강제 종료 시 "안내가 중단되었습니다. 눌러서 재개" 알림으로 처리한다.
- 필요 권한: `ACCESS_FINE_LOCATION`, `ACCESS_BACKGROUND_LOCATION`, `POST_NOTIFICATIONS`, `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_LOCATION`, `INTERNET`, 배터리 최적화 제외 요청.

## 3. 구조

### 3.1 모듈

```
bikeRecoder/
├─ app/                      Android 앱 (Compose UI, 서비스, 지도, DB, 검색)
├─ core/                     순수 Kotlin(JVM), Android 의존 없음
│   ├─ model                 Trip, Waypoint, Route, Instruction 등
│   ├─ navigation            진행 위치 계산, 경로 이탈, 도착 판정, 도착 예정 시각
│   └─ voice                 한국어 안내 문구 생성, 안내 스케줄러
├─ routing-brouter/          순수 JVM — BRouter 호출, 결과를 core 모델로 변환
│   └─ profiles/             cycleway-first.brf / balanced.brf / shortest.brf
└─ third_party/brouter/      BRouter v1.7.10: brouter-core, -mapaccess, -expressions, -codec, -util (원본 그대로)
```

`core`와 `routing-brouter`는 Android 없이 JVM에서 테스트한다.

### 3.2 app 패키지

| 패키지 | 역할 | 인터페이스(교체 지점) |
|---|---|---|
| `ui` | 온보딩, 지도 메인, 검색, 경로 계획, 안내 중, 설정 화면 | |
| `map` | MapLibre 래퍼, 경로선·경유지 마커 | `TileSource` |
| `offline` | `CorridorDownloader`(경로 주변 지도), `SegmentDownloader`(rd5) | |
| `search` | 카카오 로컬 클라이언트 | `PlaceSearch` |
| `location` | 위치 수신, `NavigationService`(포그라운드) | `LocationSource` (테스트 시 GPX 재생) |
| `tts` | TTS 래퍼, 오디오 포커스 | `VoiceOutput` (테스트 시 발화 기록) |
| `data` | Room, DataStore | |

### 3.3 안내 중 데이터 흐름

```
GPS ─► LocationSource ─► NavigationService(포그라운드)
                              ├─► core.navigation: 진행 위치 / 이탈 / 다음 안내
                              │        └─ 이탈 시 ─► routing-brouter 재탐색
                              ├─► core.voice ─► VoiceOutput(TTS)
                              └─► StateFlow ─► 안내 화면
```

## 4. 화면 흐름

```
[온보딩] ─► [지도 메인] ─┬─► [장소 검색] ─┐
                        ├─ 지도 길게 누르기 ┤
                        │                 ▼
                        │           [경로 계획] ─► (일정 유형 확인) ─► [안내 중] ─► [도착/종료]
                        └─► [설정]
```

### 4.1 온보딩 (첫 실행)
권한별 이유 설명 후 순서대로 요청: 정밀 위치 → 백그라운드 위치("항상 허용" 설정 화면 이동) → 알림 → 배터리 최적화 제외 → 경로 데이터(약 80MB) 다운로드(와이파이 권장, 진행률). 경로 데이터가 없으면 경로 계산 버튼은 비활성화된다. 사진·Health Connect 권한은 이후 단계에서 해당 기능 첫 사용 시 요청한다.

### 4.2 지도 메인
- 상단 검색창, 현재 위치 지도.
- 길게 누르기 → 하단 시트: 주소(coord2address) 표시, [목적지로 설정] / [경유지로 추가].
- 진행 중인 여행이 있으면 배너: "🚩 {목적지} · 여러 날 {N}일차 [이어서 안내]".

### 4.3 장소 검색
카카오 키워드 검색, 현재 위치 기준 거리순(`sort=distance`). 결과 선택 → 4.2와 같은 하단 시트.

### 4.4 경로 계획
- 출발: 현재 위치. 경유지 목록(끌어서 순서 변경, 삭제, 추가), 목적지.
- 경로 성향 칩: [자전거도로 최우선] [균형] [최단거리]. 기본값은 설정값(초기 자전거도로 최우선).
- 변경할 때마다 즉시 재계산.
- 요약: 총 거리, 예상 시간(15km/h 기준), 누적 오르막, **자전거도로 비율(%)**.
- [안내 시작] → 일정 유형 확인(5장) → 안내 즉시 시작 → 경로 주변 지도는 뒤에서 다운로드(상단 진행 표시).

### 4.5 안내 중
- 상단 회전 카드: 아이콘, 남은 거리, 다음다음 회전 미리보기.
- 지도: 진행 방향 위, 3D 기울임, 자동 추적. 사용자가 지도를 움직이면 추적 중지 + [현재 위치로] 버튼.
- 하단: 남은 거리 · 도착 예정 시각 · 현재 속도. [음소거] [전체 경로] [종료].
- 안내 화면을 보는 동안 화면 켜짐 유지(설정으로 끌 수 있음). 화면이 꺼지거나 다른 앱으로 가도 음성 안내 계속.

### 4.6 도착과 종료

| 상황 | 당일 | 여러 날 |
|---|---|---|
| 최종 목적지 도착 | "목적지에 도착했습니다" → 여행 완료. 완료 화면에 [여러 날로 바꾸기] | 여행 완료 |
| 도중 [종료] | "안내를 끝낼까요?" → 완료 | [오늘은 여기까지] / [여행 완료] |

- 여행 완료 → 해당 여행의 오프라인 지도 삭제.
- 오늘은 여기까지 → 안내만 중지. 여행·남은 경유지·오프라인 지도 유지.
- [여러 날로 바꾸기] → 완료를 취소하고 여러 날 여행(진행 중)으로 되돌린다. 오프라인 지도는 이미 삭제되었으므로 다음 [이어서 안내] 때 다시 받는다.

### 4.7 다음 날 이어가기
지도 메인 [이어서 안내] → 현재 위치에서 미방문 경유지와 목적지까지 재계산 → 안내 시작.

### 4.8 설정
기본 경로 성향, 음성 안내 켜기/끄기, 안내 중 화면 켜짐 유지, 오프라인 지도 와이파이에서만 받기, 경로 데이터 관리(업데이트 확인·삭제), 내려받은 지도 용량 확인·삭제, 앱 버전 표시(V1.0.0).

## 5. 여행(Trip) 흐름

- 내비게이션 목적지 설정 또는 (이후 단계의) 기록 시작 중 **먼저 하는 쪽에서 한 번만** 묻는다: "오늘 하루 일정인가요, 여러 날 일정인가요?" 기본값 당일.
- 진행 중인 여러 날 여행이 있으면 대신 "{여행} 여행을 이어서 진행할까요?"를 묻는다. 아니요 → 기존 여행을 완료 처리하고 새 일정 시작.
- 내비게이션과 기록은 같은 Trip을 공유한다.
- 여러 날 여행이 진행 중인데 마지막 활동 후 **3일 이상** 지나면 앱 실행 시 "완료 처리할까요?"를 한 번 묻는다.

상태 전이:

```
          [안내 시작: 당일] ──────────────► ACTIVE(당일) ──도착/종료──► COMPLETED
                                                                        │ [여러 날로 바꾸기]
                                                                        ▼
          [안내 시작: 여러 날] ───────────► ACTIVE(여러 날) ◄────────────┘
                                             │  │ [오늘은 여기까지] → ACTIVE 유지(안내만 중지)
                                             │  └ [이어서 안내] → 안내 재개
                                             └── 도착 / [여행 완료] / 3일 방치 후 확인 ──► COMPLETED
```

## 6. 핵심 로직

### 6.1 경로 성향 프로필 (BRouter .brf, `trekking` 기반)

비용 계수(클수록 회피):

| 도로 유형 | 자전거도로 최우선 | 균형 | 최단거리 |
|---|---|---|---|
| `highway=cycleway`, 자전거 노선 관계(icn/ncn/rcn/lcn) | 1.0 | 1.0 | 1.0 |
| residential / service / living_street | 1.5 | 1.2 | 1.0 |
| tertiary | 2.5 | 1.5 | 1.1 |
| secondary | 4.0 | 2.0 | 1.2 |
| primary | 10 | 3.0 | 1.5 |
| motorway, trunk, `motorroad=yes`, `bicycle=no` | 통행 불가 | 통행 불가 | 통행 불가 |

- 한국의 자동차전용도로(강변북로, 올림픽대로 등) 차단을 위해 `motorroad=yes` 금지가 필수다.
- 자전거도로 최우선 프로필은 `stick_to_cycleroutes=1`을 사용한다.
- **자전거도로 비율** = (cycleway, 자전거 노선, 자전거 전용차로 `cycleway=lane|track` 구간 길이) ÷ 전체 길이. BRouter 결과의 구간별 way 태그로 계산한다.
- BRouter `turnInstructionMode`는 1(auto)을 쓰고, GeoJSON `voicehints`(`[트랙 인덱스, 명령, 출구 번호, 다음까지 거리, 각도]`)를 `Instruction` 모델로 변환한다. 명령: TL, TR, TSLL, TSHL, TSLR, TSHR, KL, KR, TU, RNDB 등.

### 6.2 진행 위치 계산
- 현재 위치를 경로선에 투영한다. 탐색은 **직전 매칭 지점부터 앞쪽 일정 구간(약 500m)**만 한다. 갔다 돌아오는 경로에서 반대편 구간으로 튀는 것을 막는다. 앞쪽 구간에서 못 찾으면(이탈) 이탈 판정으로 넘긴다.
- 산출: 경로상 진행 거리, 남은 거리, 다음 회전, 다음 경유지.

### 6.3 경로 이탈과 재탐색
- 경로와의 수직 거리 **40m 이상이 8초 이상** 지속되면 이탈.
- GPS 정확도(accuracy)가 30m보다 나쁜 위치는 판정에서 제외.
- 재탐색: 현재 위치·진행 방향(heading) → 미방문 경유지 → 목적지. 재탐색 간 최소 15초.
- 재탐색 실패 시 기존 경로 유지, "경로를 다시 찾지 못했습니다" 안내, 30초 후 재시도.

### 6.4 도착 판정
- 경유지·목적지 30m 이내 진입 → 도착.
- 50m 이내로 접근 후 거리가 다시 증가하기 시작하면 지나침으로 보고 도착 처리.
- 경유지 도착 시 `Waypoint.visitedAt` 저장 + "경유지에 도착했습니다" 안내.

### 6.5 도착 예정 시각
- 기준 속도: 최근 15분 이동 평균 속도(정지 구간 제외, 2km/h 미만을 정지로 간주).
- 이동 데이터 5분 미만이면 15km/h.
- 도착 예정 = 현재 시각 + 남은 거리 ÷ 기준 속도.

### 6.6 음성 안내 스케줄러
- 우선순위: 회전 > 이탈·도착 > 1km 정기.
- 회전 안내: 200m 전, 30m 전. 현재 속도 25km/h 초과 시 첫 안내를 300m 전에.
- 회전 후 50m 안에 다음 회전이 있으면 합친다: "좌회전 후 바로 우회전입니다".
- 1km 정기 안내: 오늘 이동 거리가 1km 단위를 넘을 때마다. 15초 안에 회전 안내 예정이면 회전 안내 후로 미룸.
  - 문구: "{n}킬로미터 이동. 남은 거리 {x.x}킬로미터, 도착 예정 {오전|오후} {h}시 {m}분입니다."
  - 기록 코어 단계에서 평균 속도·이동 시간을 같은 문장에 추가한다.
- "오늘 이동 거리"는 해당 날짜의 안내 세션 이동 거리 합(정확도 30m 초과 위치 제외).
- 숫자 읽기: 1km 미만은 "{m}미터"(10m 단위 반올림), 이상은 소수 첫째 자리 킬로미터. 시각은 12시간제(정오 "오후 12시", 자정 "오전 12시").

### 6.7 경로 주변 지도 다운로드
- 경로선을 양쪽 2km 버퍼한 다각형 → `OfflineGeometryRegionDefinition`, 확대 단계 10~14.
- 경로 전체 경계 사각형 → `OfflineTilePyramidRegionDefinition`, 확대 단계 5~9.
- 다운로드 전 타일 수 추정. **15,000개 초과** 시 현재 위치부터 앞쪽 150km만 받고, 다음 [이어서 안내] 때 다음 구간을 받는다.
- 각 지역에 tripId 메타데이터를 붙이고 `OfflineRegionRef`에 기록.
- 목적지·경유지 변경 → 기존 지역 삭제 후 새 경로로 재다운로드. 여행 완료 → 삭제. 이탈 재탐색 → 유지.
- 지도 일반 캐시(ambient cache) 100MB.
- 기본은 모바일 데이터에서도 다운로드하며 시작 전 예상 용량을 표시한다. 설정 "와이파이에서만" 시 와이파이 연결까지 대기.

### 6.8 경로 데이터 파일
- 앱 내부 저장소 `files/segments4/`에 저장. 다운로드 중 `.part`, 완료 후 크기 확인 → 이름 변경.
- 설정에서 서버 `Last-Modified`와 비교해 업데이트.

### 6.9 오류 처리

| 상황 | 처리 |
|---|---|
| 카카오 401 | "API 키가 올바르지 않습니다. secrets.json을 확인하세요" |
| 카카오 403 | "카카오맵 사용 설정(제품 설정)이 꺼져 있습니다" |
| 네트워크 없음 | 검색 불가 안내, 지도 길게 누르기 안내 |
| 경로 없음 / 데이터 없음 | 원인 표시. 재탐색 실패는 6.3 |
| 장거리 계산 | 제한 60초 + 진행 표시. 초과 시 "경유지를 추가해 주세요" |
| GPS 10초 이상 없음 | 화면 "GPS 신호 약함" + 음성 1회 |
| 한국어 TTS 없음 | 화면 안내만, 최초 1회 TTS 설치 안내 |
| 시스템 강제 종료 | "안내가 중단되었습니다. 눌러서 재개" 알림. 상태는 DB에 있음 |

### 6.10 저장 데이터 (Room)
- `Trip(id, type[SINGLE_DAY|MULTI_DAY], status[ACTIVE|COMPLETED], profile, createdAt, lastActiveAt, completedAt)`
- `Waypoint(id, tripId, order, name, lat, lon, isDestination, visitedAt?)`
- `OfflineRegionRef(id, tripId, mapLibreRegionId, kind[CORRIDOR|OVERVIEW], createdAt)`
- 경로 자체는 저장하지 않고 매번 현재 위치에서 재계산한다.
