# 주행 사용성 개선 설계 (V1.1.0 포함)

- 작성일: 2026-10-18
- 대상 버전: V1.1.0 (미확정 상태이므로 함께 포함)
- 선행: `2026-10-05-navigation-design.md`, `2026-10-12-recording-core-design.md`
- 상태: 설계 사용자 승인(2026-10-18 채팅). 사용자 실주행 피드백(2026-10-18)에서 출발

## 0. 배경 (사용자 피드백)

1. 첫 화면에서 집·회사 같은 지정 장소를 눌러 바로 목적지로 쓰고 싶다.
2. 장소 검색 결과가 키보드 뒤에 가려 끝까지 내려갈 수 없다.
3. 안내 화면의 [종료] 안에 숨은 "안내만 끝내기"는 알기 어렵다. "안내 취소 · 기록 계속"이 바로 보여야 한다.
4. 안내 없이 기록하다가 새 목적지를 정해 다시 안내받고 싶다. 기록은 유지하고, 이어서 쌓을지 구간을 나눌지 고를 수 있어야 한다.
5. 경로 계획 화면에서도 지도를 길게 눌러 지점을 추가하고 싶다.

## 1. 즐겨찾기

### 1.1 화면
- 지도 메인 검색창 아래 가로 칩 줄: **[🏠 집] [🏢 회사] [★ {이름}]…** (가로 스크롤). 등록된 것만 표시하며, 하나도 없으면 줄을 숨긴다.
- 칩을 누르면 그 장소를 **목적지로 설정**하고(`PlanViewModel.setDestination`) 경로 계획 화면으로 간다.
- 칩을 길게 누르면 메뉴: [이름 바꾸기] [삭제] (삭제는 확인 "즐겨찾기에서 삭제할까요?").

### 1.2 등록
- 장소 하단 시트(지도 메인 길게 누르기, 검색 결과, 경로 계획 길게 누르기)에 **[즐겨찾기에 저장]** 버튼을 추가한다.
- 누르면 이름 선택 대화상자: [집] [회사] [직접 입력](텍스트, 1~20자). 집·회사는 하나씩만: 이미 있으면 "기존 집을 이 장소로 바꿀까요?" 확인 후 교체.
- 직접 입력 이름 중복은 허용하지 않는다("같은 이름의 즐겨찾기가 있습니다").
- 최대 20개. 넘으면 "즐겨찾기는 20개까지 저장할 수 있습니다".

### 1.3 저장
- Room `favorite_place(id, kind[HOME|WORK|CUSTOM], name, lat, lon, address?, createdAt)` — DB v3, 2→3 AutoMigration(테이블 추가만). 정렬: 집 → 회사 → 직접 입력(생성 순).

## 2. 검색 결과와 키보드
- 검색 화면 결과 목록이 키보드(IME) 높이만큼 아래 여백을 두도록 한다(`imePadding`/`WindowInsets.ime`). 키보드가 떠 있어도 마지막 결과까지 스크롤된다.
- 결과 목록을 스크롤하기 시작하면 키보드를 내린다(선택 사항이 아닌 기본 동작).

## 3. 안내 화면 버튼 (기록 중일 때)
- 기록 중인 안내의 하단 버튼: **[음소거] [안내 취소 · 기록 계속] [주행 종료]**. ([전체 경로]는 지도 위 작은 버튼으로 옮긴다.)
- [안내 취소 · 기록 계속]: 확인 없이 즉시 안내만 끝내고(`END_GUIDANCE_ONLY`) 기록 화면으로 간다. 음성 "안내를 마칩니다. 기록은 계속됩니다".
- [주행 종료]: 기존 종료 대화상자(일정 유형별 선택지) 그대로.
- 기록하지 않는 안내: V1.0.0 버튼 구성 그대로([음소거] [전체 경로] [종료]).

## 4. 기록 중 새 목적지 안내
### 4.1 진입
- 기록 화면(지도 페이지 하단 요약 위)에 **[목적지 정하기]** 버튼. 누르면 검색 화면으로 가며, 즐겨찾기 칩·지도 길게 누르기도 사용할 수 있다.
- 목적지를 정하면 경로 계획 화면 → [안내 시작].

### 4.2 여행 처리
- 기록 중인 여행이 있으면 [안내 시작]은 **그 여행에** 안내를 붙인다: 일정 유형을 묻지 않고 `TripManager.changeStops(tripId, 계획 경유지)` 후 그 여행으로 안내를 시작한다. 기록 중인 여행을 끝내고 새 여행을 만들지 않는다(V1.1.0의 `endForAnotherTrip` 경로는 기록 중이 아닐 때만 쓰인다).
- 기록 중이 아닐 때는 기존 흐름 그대로(일정 유형 확인 / 이어서 진행).

### 4.3 기록 이어서 / 나누기
- 설정 **"안내를 새로 시작할 때 기록"**: [자동으로 이어서 기록] / [자동으로 새 구간 나누기] / [매번 물어보기](기본값).
- 매번 물어보기: [안내 시작] 시 대화상자 "기록을 어떻게 할까요?" [이어서 기록] [새 구간으로 나누기] [취소].
- 이어서 기록: 현재 구간에 계속 쌓는다(기록 세션 그대로, 1km 안내는 합친 문장으로 전환).
- 새 구간으로 나누기: 현재 구간을 닫고(`SEGMENT_ONLY`, 요약 표시 없음) 같은 여행에 새 구간을 열어 기록을 시작한다. 음성 "새 구간으로 기록을 시작합니다".
- 어느 쪽이든 기록이 끊기는 동안 받은 위치는 버리지 않는다(나누기는 같은 위치 흐름에서 즉시 새 세션 시작).

## 5. 경로 계획 화면 길게 누르기
- 경로 계획 지도 길게 누르기 → 지도 메인과 같은 장소 하단 시트(주소 조회, "주소를 확인하는 중…", 실패 시 좌표): **[경유지로 추가] [목적지로 설정] [즐겨찾기에 저장]**.
- [경유지로 추가]: 목적지 바로 앞에 추가. [목적지로 설정]: 목적지만 교체, 경유지 유지. 화면은 경로 계획에 머물고 경로를 다시 계산한다.
- 길게 누르기·주소 조회 로직은 지도 메인과 공통 부품으로 만든다.

## 6. 검증
### 6.1 PC 테스트
- 즐겨찾기: 집/회사 하나씩 교체 확인, 직접 입력 중복 거부, 20개 제한, 정렬, 칩 → 목적지 설정.
- 기록 중 새 안내: 기록 중 [안내 시작] → 같은 여행에 changeStops, 새 여행 생성 없음; 설정 3종(이어서/나누기/묻기) 각각의 결과(구간 수, 세션 유지, 음성); 묻기에서 [취소]면 아무것도 안 함.
- [안내 취소 · 기록 계속]: 안내 Idle, 기록 Active 유지, 음성 문구.
- 경로 계획 길게 누르기: 경유지가 목적지 앞에 들어감, [목적지로 설정]이 경유지를 지우지 않음.
- DB 2→3 마이그레이션.
### 6.2 휴대폰 테스트
- 검색 결과가 키보드가 떠 있을 때 마지막 항목까지 스크롤(Compose UI 테스트).
- 즐겨찾기 칩 줄 표시·길게 누르기 메뉴, 안내 화면 버튼 구성(기록 중/아님), 기록 화면 [목적지 정하기].
### 6.3 실주행 확인
1. 집 즐겨찾기로 안내 시작이 바로 되는가.
2. 안내 중 [안내 취소 · 기록 계속] 후 기록이 끊기지 않는가.
3. 기록 중 새 목적지로 안내 시작 시 설정대로(이어서/나누기/묻기) 동작하고, 기록 목록에 같은 여행으로 보이는가.
4. 경로 계획 화면에서 길게 눌러 경유지 추가.
