# 버전 관리 규칙

bikeRecoder는 **Semantic Versioning(유의적 버전)** 을 개인 앱에 맞게 적용한다.

```
V MAJOR . MINOR . PATCH
   1   .   0   .   0
```

## 1. 각 자리를 올리는 기준

| 자리 | 올리는 경우 | 예 |
|---|---|---|
| **MAJOR** | 기존 데이터나 사용 방식과 **호환되지 않는** 변경. 이전 버전의 기록을 그대로 쓸 수 없거나(DB 마이그레이션 불가), 앱 구조·사용 흐름을 전면 개편할 때 | 기록 저장 형식 전면 교체 → 2.0.0 |
| **MINOR** | **새 기능 추가**. 기존 데이터와 호환됨. 하위 프로젝트 하나가 완료되면 MINOR를 올린다 | 기록 코어 완성 → 1.1.0 |
| **PATCH** | **버그 수정, 성능·문구 개선** 등 기능 추가 없는 변경 | 재탐색 오작동 수정 → 1.0.1 |

- 상위 자리를 올리면 하위 자리는 0으로 되돌린다. (1.2.3 → 1.3.0, 1.3.0 → 2.0.0)
- 한 번 배포(설치)한 버전 번호는 다시 쓰지 않는다.
- 판단이 애매하면: 사용자가 새로 할 수 있는 일이 생겼으면 MINOR, 아니면 PATCH.

## 2. 로드맵상 버전

| 버전 | 내용 |
|---|---|
| V1.0.0 | 내비게이션 |
| V1.1.0 | 기록 코어 |
| V1.2.0 | 여행과 후처리 |
| V1.3.0 | 영상과 이미지 생성 |

각 버전은 해당 하위 프로젝트 스펙의 검증(자동 테스트 + 실주행 체크리스트)을 모두 통과해야 확정된다.

## 3. 개발 중 버전 표기

- 개발 중인 빌드(debug)는 다음 목표 버전 뒤에 `-dev`를 붙인다. 예: `1.0.0-dev`
- 검증을 통과해 확정한 빌드(release)만 `-dev` 없이 `1.0.0`으로 표기한다.

## 4. Android 버전 값

`app/build.gradle.kts` 한 곳에서 MAJOR/MINOR/PATCH를 정의하고 아래 값을 계산한다.

- `versionName = "MAJOR.MINOR.PATCH"` (앱 화면에는 `V1.0.0`처럼 V를 붙여 표시)
- `versionCode = MAJOR × 10000 + MINOR × 100 + PATCH`
  - 1.0.0 → 10000, 1.0.1 → 10001, 1.1.0 → 10100, 2.0.0 → 20000
  - MINOR와 PATCH는 각각 99를 넘지 않는다.

## 5. 기록

- 버전을 확정할 때마다 `CHANGELOG.md`에 날짜와 변경 내용을 기록한다. (추가 / 변경 / 수정 / 삭제로 구분)
- Git 태그는 소문자 `v`를 붙인다: `v1.0.0`
